# ADR 0012: Review links name 127.0.0.1, not localhost

**Status:** Accepted (30.09.2026, Phase 3). Amends the link format in ADR 0011; the
port range, lock and takeover stand.

## Context

The server binds `127.0.0.1` only (ADR 0011). Links said `localhost`, which a system
may resolve to `::1` first, where a different program could be listening on the same
port. From Phase 3 the page also keeps state per origin: stored marks and the last
known `stale-hours` live in the browser's `localStorage`, and `localhost:7777` and
`127.0.0.1:7777` are different origins.

## Decision

Every link the renderer hands out is `http://127.0.0.1:<port>/review/<slug>.html`. The
server still accepts both `Host: 127.0.0.1:<port>` and `localhost:<port>`, and `Origin`
must match whichever the page was opened on.

## Consequences

- The address in the link is the address that is bound, so no other program can answer it.
- Marks made on a page opened as `localhost` do not show on the same page opened as
  `127.0.0.1`. Nothing has been released with `localhost` links, so no user loses marks.
- Changing the host again after v1.0.0 would orphan every user's marks. Treat it as fixed.

## Alternatives

- **Keep `localhost` and also bind `::1`.** Two sockets per server and two lock-free races
  on the port range, for no gain to the user.
- **Keep `localhost` as it was.** Leaves the `::1` gap (Phase 2 review, minor M-6) open
  exactly when per-origin state starts to matter.
